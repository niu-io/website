开发者和团队通过模型 API 构建应用、使用编程工具，并在 Chat 和 Video 中探索想法。随着用量增长，他们需要的不只是另一个 API 密钥，还需要知道可以使用哪些模型、请求发生了什么，以及词元预算花在了哪里。

牛元是面向这些用户的词元管理平台，聚焦性能、可靠性与经济性：高效接入模型、理解失败原因，让开支清晰可见、可以控制。

## 性能：高效接入模型

通过工作空间 API 密钥，使用文档中列出的 OpenAI 兼容与 Anthropic 兼容接口接入应用和编程工具。切换应用使用的模型前，请先检查模型支持的能力。

Rust 网关支持流式响应，并公开了[网关基准测试](/docs/guides/gateway-benchmarks/)。这些数据来自历史版本与确定性的模拟上游，不代表每个模型、每种工作负载都能达到相同的端到端延迟或吞吐量。

## 可靠性：理解每一次请求

请求历史集中展示状态、已记录的尝试、上报的词元用量、耗时和费用。你可以区分请求在发送前被拒绝、上游返回错误，以及响应中途断开等情况。

配置的模型路由支持有边界的故障转移。结果不确定的请求不能被盲目重放，否则可能重复执行或再次计费。缺失的用量证据会明确标示。支持的行为与限制见[请求证据指南](/docs/concepts/execution-observation/)。

## 经济性：让词元开支清晰可见

查看模型标价、实际词元用量与请求费用，为应用和团队设置工作空间及 API 密钥预算。进行中的请求会先预留额度，并计入相应的开支限制。

经济性意味着做出有依据的选择、控制开支，并不意味着每个模型都更便宜。模型价格和可用性取决于已配置的报价；尚未解决的计费证据必须与已确认费用保持区分。

## 在同一工作空间使用 API、Chat 和 Video

从应用调用 API，在 Chat 中比较模型，并重新打开已保存的对话。支持的视频工作流提供持久化的任务状态和经授权的结果访问。具体可用性取决于模型配置和权限。

牛元的开源网关、控制台、模型目录和文档也可配合 PostgreSQL 自托管。部署与能力验收边界见[部署指南](/docs/deployment/single-container/)和[发布验收矩阵](https://github.com/niu-io/niu/blob/main/docs/releases/first-release.md)。
